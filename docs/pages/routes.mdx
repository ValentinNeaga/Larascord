Every route Larascord registers lives under the configured prefix and is named with a `larascord.` prefix, so it can never collide with a route of your application.

| Route Name | URI | Description | Action | Method |
| ---------- | ---- | ----------- | ------ | ------ |
| `larascord.redirect` | `/larascord/redirect` | Sends the visitor to Discord's OAuth2 authorization page. | `DiscordController@redirect` | `GET` |
| `larascord.callback` | `/larascord/callback` | Callback route for Discord OAuth2 authentication. | `DiscordController@callback` | `GET` |
| `larascord.logout` | `/larascord/logout` | Invalidates the current session. | `DiscordController@logout` | `POST` |
| `larascord.link` | `/larascord/link` | Links a Discord account to the authenticated user. | `DiscordController@link` | `GET` |
| `larascord.unlink` | `/larascord/unlink` | Revokes the access token and unlinks the Discord account. | `DiscordController@unlink` | `DELETE` |

<Callout type="info">
    The `larascord.link` and `larascord.unlink` routes use the `web` and `auth` middleware. You can change that with the `routes.authenticated_middleware` option.
</Callout>

## Where the user lands afterwards

Larascord works out the return URL when the flow starts, not when the user comes back, because by then the only thing the session remembers is the route that sent them to Discord.

The first of these that applies wins:

<Steps>
    ### The `redirect_to` query parameter
    ```blade
    <a href="{{ route('larascord.redirect', ['redirect_to' => url()->current()]) }}">Log in with Discord</a>
    ```

    ### The page the user was on, for `larascord.link` only
    Linking is something a user does from a settings page, so they are sent back to it without you having to pass anything.

    ### The URL Laravel's `auth` middleware stored
    This is what sends somebody who was heading for a protected page back to it once they have logged in.

    ### `redirect_login` from `config/larascord.php`
</Steps>

<Callout type="warning">
    A return URL pointing at another host, or at one of Larascord's own routes, is ignored. The first would let somebody use your login route to bounce visitors to a site of their choosing, and the second would send the user straight back to Discord in a loop.
</Callout>

## Logging in while already logged in

Visiting `larascord.redirect` or `/login` while logged in is a login, not a linking attempt. The Discord profile is refreshed, the session is kept if it belongs to the same user, and the user lands on the return URL above.

<Callout type="info">
    If the Discord account belongs to a different user than the one in the session, that user is logged in instead. Use `larascord.link` when you want to attach a Discord account to the account that is already signed in.
</Callout>

## The login route alias

Laravel's `auth` middleware redirects guests to a route named `login`. Larascord does not register one unless you ask for it, because your application may already have it.

```dotenv filename=".env"
LARASCORD_LOGIN_ALIAS=true
```

This registers `GET /login`, named `login`, which sends the visitor straight to Discord.

## Registering the routes yourself

Set `routes.enabled` to `false` and point your own routes at the controller.

```php filename="routes/web.php" showLineNumbers
use Jakyeru\Larascord\Http\Controllers\DiscordController;

Route::get('/auth/discord', [DiscordController::class, 'redirect'])->name('larascord.redirect');
Route::get('/auth/discord/callback', [DiscordController::class, 'callback'])->name('larascord.callback');
```

<Callout type="warning">
    Keep the `larascord.redirect` and `larascord.callback` names, and make sure `redirect_uri` in `config/larascord.php` matches the URI of your callback route and the redirect url registered with Discord.
</Callout>
