<Callout type="warning">
    Version 8 is a rewrite of how Larascord stores users. It is not backwards compatible with version 7 and the steps below have to be followed in order. Take a backup of your database before you start.
</Callout>

## What changed and why

Up to version 7 Larascord owned your application. It installed Laravel Breeze, overwrote `resources/views`, replaced `routes/web.php`, shipped its own `App\Models\User` and kept the Discord profile in your `users` table with the Discord snowflake as the primary key. That is fine for a brand new project and impossible for everything else.

Version 8 keeps to itself:

* Larascord stores the Discord profile in its own `larascord_accounts` table and links it to one of your users through a `user_id` foreign key. Your `users` table is yours again.
* No views, no assets and no Laravel Breeze. Your UI is untouched.
* No `routes/web.php` and no `login`, `logout` or `profile.destroy` routes. Every route Larascord registers lives under its prefix and is named `larascord.*`.
* Removing the package and dropping the two Larascord tables leaves your application working.

<Steps>
    ### Follow [Laravel's upgrade guide](https://laravel.com/docs/13.x/upgrade) to upgrade to Laravel 13

    ### Update the following dependencies in `composer.json`
    * `jakyeru/larascord` to `^8.0`

    #### Run the `composer update` command
    ```bash
    composer update
    ```

    <Callout type="info">
        Laravel Breeze is no longer a dependency of Larascord. If you want to keep the views and routes it gave you, add `laravel/breeze` to your own `composer.json`. They will keep working, because Larascord no longer touches them.
    </Callout>

    ### Publish the new configuration file
    ```bash
    php artisan larascord:publish --force
    ```

    <Callout type="warning">
        This overwrites `config/larascord.php`. Write down your `guilds`, `guild_roles` and any message you customised before you run it, then copy them into the new file.
    </Callout>

    ### Publish and run the new migrations
    ```bash
    php artisan larascord:publish --migrations
    ```
    ```bash
    php artisan migrate
    ```
    This creates the `larascord_accounts` and `larascord_access_tokens` tables. Nothing is dropped yet.

    ### Move your existing users over
    Your version 7 `users` table holds the Discord profile with the snowflake as the `id`. The following migration copies every row into `larascord_accounts`, keeps the same `id` so your foreign keys stay valid, and moves the access tokens across.

    ```bash
    php artisan make:migration move_discord_profiles_to_larascord_accounts
    ```

    ```php filename="database/migrations/move_discord_profiles_to_larascord_accounts.php" showLineNumbers
    use Illuminate\Database\Migrations\Migration;
    use Illuminate\Support\Facades\DB;

    return new class extends Migration
    {
        public function up(): void
        {
            DB::table('users')->orderBy('id')->chunkById(100, function ($users) {
                foreach ($users as $user) {
                    $accountId = DB::table('larascord_accounts')->insertGetId([
                        'user_id' => $user->id,
                        'discord_id' => $user->id,
                        'username' => $user->username,
                        'global_name' => $user->global_name,
                        'discriminator' => $user->discriminator,
                        'email' => $user->email,
                        'avatar' => $user->avatar,
                        'verified' => $user->verified,
                        'banner' => $user->banner,
                        'banner_color' => $user->banner_color,
                        'accent_color' => $user->accent_color,
                        'locale' => $user->locale,
                        'mfa_enabled' => $user->mfa_enabled,
                        'premium_type' => $user->premium_type,
                        'public_flags' => $user->public_flags,
                        'created_at' => $user->created_at,
                        'updated_at' => $user->updated_at,
                    ]);

                    $token = DB::table('discord_access_tokens')->where('user_id', $user->id)->first();

                    if ($token) {
                        DB::table('larascord_access_tokens')->insert([
                            'discord_account_id' => $accountId,
                            'access_token' => $token->access_token,
                            'refresh_token' => $token->refresh_token,
                            'token_type' => $token->token_type,
                            'expires_in' => $token->expires_in,
                            'expires_at' => $token->expires_at,
                            'scope' => $token->scope,
                            'created_at' => $token->created_at,
                            'updated_at' => $token->updated_at,
                        ]);
                    }
                }
            });
        }

        public function down(): void
        {
            DB::table('larascord_access_tokens')->truncate();
            DB::table('larascord_accounts')->truncate();
        }
    };
    ```

    ```bash
    php artisan migrate
    ```

    <Callout type="info">
        The access tokens are encrypted with your `APP_KEY` and are copied across as they are, so your users stay logged in to Discord without having to authorize your application again.
    </Callout>

    ### Clean up your `users` table
    The Discord columns are now stored by Larascord. Drop the ones you do not use yourself and add whatever your application needs, for example a `name` column.

    ```bash
    php artisan make:migration clean_up_users_table
    ```

    ```php filename="database/migrations/clean_up_users_table.php" showLineNumbers
    use Illuminate\Database\Migrations\Migration;
    use Illuminate\Database\Schema\Blueprint;
    use Illuminate\Support\Facades\DB;
    use Illuminate\Support\Facades\Schema;

    return new class extends Migration
    {
        public function up(): void
        {
            Schema::table('users', function (Blueprint $table) {
                $table->string('name')->nullable()->after('id');
            });

            DB::statement('UPDATE users SET name = COALESCE(global_name, username)');

            Schema::table('users', function (Blueprint $table) {
                $table->string('name')->nullable(false)->change();

                $table->dropColumn([
                    'username',
                    'global_name',
                    'discriminator',
                    'avatar',
                    'verified',
                    'banner',
                    'banner_color',
                    'accent_color',
                    'locale',
                    'mfa_enabled',
                    'premium_type',
                    'public_flags',
                ]);
            });

            Schema::dropIfExists('discord_access_tokens');
        }

        public function down(): void
        {
            //
        }
    };
    ```

    ```bash
    php artisan migrate
    ```

    <Callout type="warning">
        Keep any column you query yourself. If your application reads `$user->username` in a view or a job, either keep the column and fill it yourself, or read it from `$user->discordAccount->username` instead.
    </Callout>

    ### Update your `User` model
    Version 7 shipped an `App\Models\User` that belonged to Larascord. The model is yours now. Remove every Discord column from `$fillable` and `$casts` and keep the trait only if you use its methods.

    ```php filename="app/Models/User.php" showLineNumbers {4, 8, 14}
    namespace App\Models;

    use Illuminate\Foundation\Auth\User as Authenticatable;
    use Jakyeru\Larascord\Traits\InteractsWithDiscord;

    class User extends Authenticatable
    {
        use InteractsWithDiscord;

        protected $fillable = [
            'name',
            'email',
        ];
    }
    ```

    ### Rename the trait methods you call
    The trait no longer holds the Discord profile itself, so its methods are prefixed and no longer collide with anything in your own model.

    | Version 7 | Version 8 |
    | --- | --- |
    | `$user->getAvatar()` | `$user->getDiscordAvatar()` |
    | `$user->getTagAttribute()` | `$user->getDiscordTag()` |
    | `$user->accessToken` | `$user->discordAccount->accessToken` |
    | `$user->getAccessToken()` | `$user->getDiscordAccessToken()` |
    | `$user->refreshAccessToken()` | `$user->discordAccount->refreshAccessToken()` |
    | `$user->getGuilds()` | `$user->getDiscordGuilds()` |
    | `$user->getGuildMember($guildId)` | `$user->getDiscordGuildMember($guildId)` |
    | `$user->joinGuild($guildId)` | `$user->joinDiscordGuild($guildId)` |
    | `$user->getConnections()` | `$user->getDiscordConnections()` |

    The Discord profile itself is read from the account:

    ```php
    $user->discordAccount->username;
    $user->discordAccount->discord_id;
    $user->discordAccount->tag;
    ```

    ### Update your routes and your links
    Larascord no longer registers `login`, `logout`, `password.confirm` or `profile.destroy`, and `larascord.login` has been renamed.

    | Version 7 | Version 8 |
    | --- | --- |
    | `route('login')` | `route('larascord.redirect')` |
    | `route('logout')` | `route('larascord.logout')` |
    | `route('larascord.login')` | `route('larascord.callback')` |
    | `route('larascord.refresh_token')` | `route('larascord.link')` |
    | `route('profile.destroy')` | `route('larascord.unlink')` |

    <Callout type="info">
        If your application relies on a route named `login`, set `LARASCORD_LOGIN_ALIAS=true` in your `.env` file and Larascord will register one that redirects to Discord.
    </Callout>

    The callback URL is unchanged, so you do not have to touch your Discord application's redirect urls.

    ### Update the scopes in your `.env` file
    Scopes are a comma separated list now and the variable has been renamed.

    ```diff filename=".env"
    - LARASCORD_SCOPE=identify&email
    + LARASCORD_SCOPES=identify,email
    ```

    ### Check your redirect after login
    The `redirect_login` option still exists and two more were added: `redirect_logout` and `redirect_unlink`.
</Steps>

## Other changes worth knowing

### The callback is protected against CSRF
Larascord sends a `state` parameter to Discord and verifies it when the user comes back. If you build the authorization URL yourself, use `Larascord::authorizationUrl()` so the state is generated for you, or set `verify_state` to `false`.

### Events are real now
Version 7 copied event classes into `app/Events` during installation. Version 8 dispatches its own events from the package and you listen to them like any other event.

| Event | Dispatched when |
| --- | --- |
| `Jakyeru\Larascord\Events\DiscordAccountCreated` | A Discord account is stored for the first time |
| `Jakyeru\Larascord\Events\DiscordAccountUpdated` | A known Discord account comes back |
| `Jakyeru\Larascord\Events\DiscordAccountLinked` | A Discord account is attached to one of your users |
| `Jakyeru\Larascord\Events\DiscordAccountUnlinked` | A Discord account is removed |
| `Jakyeru\Larascord\Events\UserAuthenticated` | A user is logged in through Discord |

You can delete the classes version 7 left in `app/Events` and their listeners.

### Soft deleted users
Version 7 refused to log in a soft deleted user and had a `user_deleted` message for it. Your `users` table is yours now, so do this yourself in a listener on `UserAuthenticated`, or in your authentication guard.

### `DiscordService::joinGuild` takes a Discord ID
```diff
- (new DiscordService())->joinGuild($accessToken, $user, $guildId);
+ (new DiscordService())->joinGuild($accessToken, $discordId, $guildId);
```

### `DiscordService::createOrUpdateUser` was removed
Use `Larascord::syncAccount($discordUser, $user)` instead.
